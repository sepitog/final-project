# NeoMD File Index

This repository is documentation-first and remains in the planning phase. The files in this scaffold are designed to work together as a lightweight project control system.

## How to Use This Repository
Start with [PLAN.md](./PLAN.md) to understand the product direction and system structure. Use [AGENTS.md](./AGENTS.md) to understand the development rules, [TODO.md](./TODO.md) to track active work, [LOGBOOK.md](./LOGBOOK.md) to review project history, and [UNIT-TESTS.md](./UNIT-TESTS.md) to understand future quality expectations.

## Core System Files
- `AGENTS.md` defines the NeoMD development agent protocol and documentation enforcement rules.
- `PLAN.md` provides the strategic system overview, architecture concept, and phased roadmap.
- `FILE-INDEX.md` explains how the project documentation is organized and how the files relate.
- `TODO.md` tracks project status, priorities, and next planning targets.
- `LOGBOOK.md` records dated actions, reasoning, and project observations.

## Supporting / Future Files
- `UNIT-TESTS.md` outlines the future testing strategy for validation, logic, and output correctness.
- Additional documentation may be added later for research summaries, data references, or system decisions as the project grows.

## Repository Note
At this stage, NeoMD contains planning documentation only and no application implementation. Future structural additions should remain consistent with the system described in [PLAN.md](./PLAN.md).
